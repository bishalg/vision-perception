# ASD researcher toolkit - Work Packages (phase 8)

Designed 2026-11-03 against `dev` at `ee82015` (ADR-0012; principles in ADR-0013). MUST
ids in `technical.md`; scenarios in `acceptance.md`; status tracker
`docs/roadmap_2026q4/04_asd_phased_work_packages.md` (§0 table and §10). Tier legend: `S` =
`senior-implementer` (Opus); `I` = `implementer` (Sonnet); size `S`mall (≤ 1 day) /
`I`ntermediate (2–4 days) / `L`arge (5–7 days) for one agent. Prefix **WP-X.n** = research
toolkit.

Rules that apply to every package here:

- Each package owns the files it lists and touches nothing else. `rust/Cargo.lock`,
  `rust/.sqlx/`, `docs/spec/schemas/asd/*.json` (except where a package is told to
  commit a first version) and `apps/curv_console/package-lock.json` are regenerated by
  the main session after each wave, never edited by a package. Wave packages do not run
  `cargo sqlx prepare` and do not edit `rust/README.md`; the main session does both at
  integration (the phase 7 wave-2 rule).
- Migration number is fixed: **0026** (step 0). WP-B.21 moves to **0027** (tracker rule
  updated by this design). No other package adds a migration.
- Backend tests use `tests/common` helpers and `sqlx::test`; console tests run in mock
  mode first and add a live e2e only when the route exists; core changes are proven by
  the existing golden vectors staying byte-identical plus new goldens for new behaviour.
- Every user-facing string on the console goes into `src/messages/*.ts` with `en` and
  `ne` keys (ADR-0013 principle 2; the `ne` text may be a reviewed machine draft marked
  `// ne: draft` until WP-L.3 reviews it). No literal JSX text, no literal `aria-label`.
- Every numeric that is a product parameter comes from the registry or the effective
  config (ADR-0013 principle 1); a package that needs a new knob adds a registry row
  and two message keys, not a constant.
- A package reports: files changed, test output, what was skipped and why, and any spec
  id it could not satisfy as written (do not silently widen the scope).
