# ASD EMR-lite record, share-a-case and clinic deployment - Work Packages (phase 7)

Designed 2026-11-02 against `dev` at `fe0ed56` (ADR-0011). MUST ids in `technical.md`;
scenarios in `acceptance.md`; status tracker `docs/roadmap_2026q4/04_asd_phased_work_packages.md`
(§0 table and §9). Tier legend: `S` = `senior-implementer` (Opus); `I` = `implementer`
(Sonnet); size `S`mall (≤ 1 day) / `I`ntermediate (2–4 days) for one agent.

Rules that apply to every package here:

- Each package owns the files it lists and touches nothing else. `rust/Cargo.lock`,
  `rust/.sqlx/`, `docs/spec/schemas/asd/api-v1.json` and `apps/curv_console/package-lock.json`
  are regenerated by the main session after each wave, never edited by a package.
- `rust/README.md` is the one deliberately shared file in wave 1: a package appends its own
  `##` section at the end and touches no other line; the main session merges.
- Migration numbers are fixed here: **0024** WP-B.19, **0025** WP-I.13, **0026** WP-B.21.
  Wave 1 adds none. A package that adds or changes a `sqlx::query!` runs `cargo sqlx
  prepare --workspace` against a migrated database before reporting. **Wave 2 exception
  (2026-11-03):** wave 2 packages do not run `prepare` or edit `rust/README.md`; see "Wave 2
  amendments after wave 1".
- Backend tests use the existing `tests/common` helpers and `sqlx::test`; console tests
  run in mock mode first and add a live e2e only when the backend route exists.
- A package reports: files changed, test output, what was skipped and why, and any
  spec id it could not satisfy as written (do not silently widen the scope).

### WP-R.8 Rust converter: Android MediaPipe landmarks to gaze-pipeline inputs - `S` - size S

## Traps for implementers (phase 7)

1. **Participant tokens are not stable today.** Until A.16a lands, every clinic session
   on the server is its own participant; do not "fix" that in the backend by merging rows
   (the token is the identity; merging would be a data migration with no key). The
   console shows what the server has.
2. **`participants` rows are created by ingest with only `org_id, token`.** REC-1's
   create must use the same `INSERT … ON CONFLICT (org_id, token)` shape so a device
   posting before the console creates the record does not 409 either way.
3. **AEAD AAD includes the row id** (clinician module trap 9): generate the encounter and
   attachment UUID in Rust before encrypting; never encrypt with a placeholder id.
4. **Attachment bytes must never hit the blob store in clear.** Encrypt in the handler,
   then `put`; the blob key must not contain the file name (names can carry PHI). The
   `GET` decrypts to memory (≤ 10 MiB) and streams; no temp files.
5. **`Content-Digest` is RFC 9530**: `sha-256=:<base64>:` with the colons. Older apps
   send nothing; absent is accepted, malformed is 400. iOS computes it over the encrypted
   file bytes it actually uploads, not the plaintext.
6. **One salt per package, not per file.** `deid.rs` takes a salt; the case package must
   pass the same salt to the FHIR, JSONL and CSV renders or pseudonyms will not join. The
   salt is per export and never written into the archive.
7. **ZIP determinism**: fixed entry order, fixed timestamps, no extra fields, deflate
   level fixed; otherwise the idempotency test (same export id → same sha256) fails and
   `exports.sha256` lies after a job retry.
8. **Share routes are public.** Mount them on a router without the bearer extractor,
   with `no-store`, `X-Robots-Tag`, the rate limiter keyed by link id **and** IP
   (`ASD_TRUST_PROXY_HEADERS` decides which IP; behind Caddy it must be on), and a single
   `404` for unknown/revoked/expired-link so the endpoint does not confirm ids. The
   passcode compare is Argon2id verify (constant time by construction); never log it.
9. **The passcode is shown once.** Do not put it in the `ShareLink` DTO returned by the
   list route; the create route returns a different type (`CreatedShareLink`).
10. **Read audits are not best-effort.** `record_read` runs before the body is built, in
    its own short transaction, and a failure is a 500. Do not wrap it in `let _ =`.
11. **Audit volume.** Session detail reads will dominate `audit_log`; keep `after` tiny
    (`{"part":"clips"}`) and do not add a row per clip. O-5 handles retention.
12. **Background `URLSession` is per identifier.** Create exactly one with a fixed
    identifier (`org.curv.asd.sync.blobs`) per process and re-attach the delegate at
    launch; a second instance with the same id is an error on iOS. Upload from the
    queue's file, not from `Data`, or the system cannot resume after a kill.
13. **`isOnline` must start unknown.** Starting `true` is why launches never flush;
    starting `false` would block the first flush until the monitor reports. Use an
    optional and flush on the first `.satisfied` report.
14. **Keep the Rust backoff as the source**: the Swift test must read `AsdCore.syncBackoffSchedule()`
    and compare; do not copy the numbers into the test.
15. **409 bodies**: the backend sends `application/problem+json` for `participant-withdrawn`
    and `idempotency-key-reused` and `application/json` `{duplicate:true,…}` for replays;
    classify on the slug, then on `duplicate`, then default to `Duplicate` for an empty
    body (older servers). Property-test it.
16. **`install.sh` runs as root and writes secrets**: `umask 077` first; never echo the
    `.env`; print the key card to the terminal only (no file), and tell the user to
    photograph or copy it.
17. **`asd_app` grants**: migration 0002 revokes writes on `audit_log` for `asd_app` and
    (verify) grants the rest; the smoke test is the proof. If a later migration created a
    table without granting `asd_app`, the fix is a new migration (next free number after
    the wave), not a switch back to the owner role.
18. **Caddy `internal` mode and iOS**: `url_rules` refuses IP literals, so the clinic
    needs a DNS name even on a LAN; document the router/Pi-hole step and that the Caddy
    root certificate must be installed and *trusted* on the iPad (Settings → About →
    Certificate Trust Settings), or every upload fails TLS.
19. **Backups exclude `.env` on purpose.** A backup with the KEK beside the ciphertext
    is a plaintext backup. The key card is the key backup; `restore.sh` must refuse to
    run without `ASD_DATA_KEK` and print why.
20. **`pg_restore --clean` on a live schema with triggers**: the `audit_log` triggers
    refuse `TRUNCATE`; restore into a fresh database (`DROP DATABASE … ; CREATE`) as the
    owner role, then run `migrate`. Test exactly this in the drill, not a partial restore.
21. **Erasure replay after restore is a job**, not an inline delete: `requeue-erasure`
    enqueues; the worker must be up before the row disappears. The drill waits for the
    job and then compares.
22. **`next.config.ts` `output: "standalone"`** changes where `next start` finds files;
    the `postbuild` CSP check reads `.next/`; run `npm run build` locally before touching
    the Dockerfile and keep `CURV_API_MODE=mock npm run build` green.
23. **Android `cdylib` + `staticlib` in one crate** doubles link time but is required
    (Apple wants `.a`, Android `.so`). `cargo ndk` needs `ANDROID_NDK_HOME`; the script
    must fail with a one-line hint, not a Rust error wall. JNA must match the UniFFI
    Kotlin bindings' expectations (`jna` 5.13+, `@aar` classifier).
24. **Spike discipline (A.14)**: adult volunteers only, no child data, logs not committed;
    the sheet names devices by model, not by who owns them.
25. **Idle timeout cookies** (amended 2026-11-03 to match C.21 and technical.md HIP-2):
    refresh `curv_last_seen` on every authenticated request except prefetches
    (`Next-Router-Prefetch`, `Purpose`/`Sec-Purpose: prefetch`), or prefetches keep a tab
    "active" forever; never refresh an idle or expired session. The verdict must also stop
    non-document requests (RSC navigations, server actions) of an idle or expired session,
    not only document loads (wave 1 defect 1).
