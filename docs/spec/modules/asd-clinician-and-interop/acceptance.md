# ASD Clinician Workspace and Interoperability Bridge - Acceptance

Scenarios an owner or reviewer can run against `rust/docker-compose.yml` (with
`ASD_DATA_KEK` set) and the console in `CURV_API_MODE=live`. Each cites the spec ids it
proves. Synthetic sessions (`asd-cli synth`, `ASD_ALLOW_SYNTHETIC=true`) are the data.

| # | Scenario | Proves |
| --- | --- | --- |
| 1 | As `clinician`, open Worklist: the org's unsigned sessions appear newest first. Switch the org to `clinical.worklist_scope = flagged`: green sessions disappear. A `viewer` has no Worklist nav entry and `GET /v1/orgs/{id}/worklist` answers 403. | CW-1, CW-2, RBAC-2, UI-1 |
| 2 | Claim a session, write disposition `monitor` and an impression, save. In a second browser tab change the impression and save: the first tab's next save shows "changed elsewhere" (412). | SIGN-1, SIGN-2, SIGN-3 |
| 3 | Sign with a wrong password: 401, state unchanged, one `audit_log` row `clinical_review.sign_failed`. Sign with the right password: state `final`, the session tab shows signer name, registration, time and the content-hash prefix. | SIGN-4, SIGN-5, SIGN-9 |
| 4 | Set `clinical.cosign_policy = always`. Sign: state `awaiting_cosign`. The same user tries to cosign: 409 `cosigner-must-differ`. A second clinician cosigns: `final`. | SIGN-6 |
| 5 | Amend a final review with a reason, change the impression, sign: the timeline shows both versions; `psql` `UPDATE clinical_review_versions SET impression_ct = ... WHERE status = 'signed'` fails; `DELETE FROM clinical_signatures` fails. | SIGN-7, SIGN-8 |
| 6 | Log in as `superadmin`: sessions and metrics are readable; the review panel shows no impression; `GET /v1/participants/{id}/notes` answers 403; `POST /v1/orgs/{id}/exports` with `mode: identified` answers 403. Same as `admin`. | RBAC-3, RBAC-4 |
| 7 | `SELECT impression_ct FROM clinical_review_versions` shows ciphertext only; copying one row's ciphertext into another row makes that review answer 500 on read with a logged decrypt failure and no plaintext in logs. Stop the API without `ASD_DATA_KEK`: health is `200`, sessions load, clinical endpoints answer 503 `clinical-crypto-unavailable`. | KEY-1, KEY-2, KEY-3, KEY-6 |
| 8 | With `identity.patient_ref_mode = none`, the MRN panel says "disabled" and the API answers 409. Switch to `mrn`, set MRN `12-345` for authority `TUTH`; search for `12345` (POST form) finds the participant; the browser history, server access log and `audit_log` contain no `12345`. | MRN-2..5, UI-4, KEY-4 |
| 9 | Add two notes; correct the first: the original is shown struck through and is still in the DB unchanged; the timeline shows note headers but no text. | NOTE-1, NOTE-2, CW-3 |
| 10 | Draft a referral letter in English with one Nepali sentence, finalize with step-up, download the PDF: A4, org letterhead, Nepali text rendered correctly, signature block, both mandatory sentences, footer with an export id that appears in `exports` and `audit_log`. | NOTE-3, NOTE-4, PDF-1..5, EXJ-7 |
| 11 | Print the clinical summary of an unsigned session: banner `PRELIMINARY - NOT SIGNED`; after signing: no banner, signatures listed. veraPDF (optional) reports PDF/A-2b compliant. | NOTE-5, PDF-4, PDF-6 |
| 12 | As `researcher`, export `csv_sheets`, `deidentified`, purpose `research`, last 30 days. The ZIP opens in Google Sheets with dates as dates and no junk in A1; no participant token, MRN, session id or impression appears; pseudonyms are consistent within the file; withdrawn and non-consented sessions are counted in `manifest.json` and absent. | CSV-1..4, XC-4, XC-5, EXJ-3 |
| 13 | Same filters, `csv_excel`: opens in Excel with UTF-8 intact. A participant token crafted as `=HYPERLINK(...)` in a synthetic session shows as text, not a formula. `xlsx`: README sheet carries the watermark; numbers and dates are typed cells. | CSV-1, CSV-2, XLSX-1, XLSX-2 |
| 14 | As `researcher`, request `mode: identified`: 403. As `clinician`, request identified with purpose `research`: 400 `consent-purpose-mismatch`. | EXJ-1, EXJ-2, XC-5 |
| 15 | Download an export: the link works once within 5 minutes and then expires; after 72 h the export shows `expired` and the download answers 410; `GET /v1/participants/{id}/disclosures` still lists it. | EXJ-4, EXJ-5, EXJ-6 |
| 16 | Export `fhir_bundle` (identified) for one signed session: the bundle passes the structural checks; `Patient` has the MRN identifier and no name or birth date; `DiagnosticReport.status = final`, `resultsInterpreter` = the signer; the `Observation` id equals the one in the device's own bundle for the same session; `DocumentReference.content.attachment` is the PDF with the correct hash. Optional: HL7 FHIR validator reports no errors. | FHX-1..8 |
| 17 | Export `hl7v2` for one signed and one unsigned session: `OBR-25` `F` and `P`; timestamps end `+0545` for a Kathmandu org; `PID-3` carries the MRN with authority `TUTH`; `PID-5` is empty; a configured `code_map` replaces OBX-3 for one metric; Mirth Connect or HAPI TestPanel (optional) parses both messages. | HL7-1..7 |
| 18 | Configure an SFTP destination (server-generated key added to a test `openssh` server, host key pinned) with `trigger = on_final_sign`, format `hl7v2`. Sign a session: within a minute `<prefix><export_id>_*.hl7` and `.sha256` appear in `remote_dir`; no `.part` file remains. Change the pinned host key: the next delivery fails `host-key-mismatch` and nothing is uploaded; the signature stays `final`. | INTG-3, INTG-5, DLV-1, DLV-4..6, SIGN-10 |
| 19 | Configure a webhook to `https://127.0.0.1/...` or a hostname resolving to `10.0.0.5`: rejected at save and at send. Configure a public test receiver: the event verifies with the Standard Webhooks reference library; the body has no clinical data; the download URL in it works for 15 minutes. | DLV-2, DLV-3 |
| 20 | Set an integration secret, reload the settings page: the field is empty with a fingerprint; `audit_log` and `organizations.settings` contain no secret. | INTG-1, INTG-2, G3 |
| 21 | `cargo build -p asd-export --no-default-features --target aarch64-apple-ios` succeeds (or `cargo check`), proving the crate stays usable by the app later. `grep -rn "fetch(\|xlsx\|papaparse\|pdfmake\|jspdf" apps/curv_console/src` finds no export or format code in the console. | XC-1, UI-2 |
| 22 | `scripts/rust_test.sh` and the console gates pass; `asd-cli schema check` is clean after `api-v1.json` regeneration; every new problem slug is in `$defs/ProblemSlug`. | CTR-1..3 |
